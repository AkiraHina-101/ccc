# HyperMesh Data Names Index (per entity type)

Purpose: authoritative index of valid attribute-key strings usable with
`hm_getvalue <type> id=$id dataname=<KEY>` / `hm_getentityvalue`, enumerated
per entity type via the low-level `hm_attributeindexmax` /
`hm_attributeindexidentifier` / `hm_attributeindexvalue` triple, which is the
same mechanism the entity browser and attribute editor use internally to list
every attribute a given entity instance exposes.

## Method used

```tcl
*loadfile / *readfile <path>          ;# see "File-load command discovery" below
*clearmark <type> 1
*createmark <type> 1 "all"
set n  [hm_marklength <type> 1]
set id [lindex [hm_getmark <type> 1] 0]
set maxidx [hm_attributeindexmax <type> $id]
for {set i 1} {$i <= $maxidx} {incr i} {
    set key [hm_attributeindexidentifier <type> $id $i]
    set val [hm_attributeindexvalue <type> $id $i]
}
```

Important correction vs. the originally assumed loop: `hm_attributeindexidentifier`
/ `hm_attributeindexvalue` are **1-indexed**, not 0-indexed. Calling index `0`
raises `Index 0 is invalid! Only indices from 1 through N (inclusive) are
accepted.` The script and this doc use the corrected 1..maxidx range.

### File-load command discovery

`*loadfile` and `*tclopen` do **not** exist as Tcl commands in this install
(`info commands *loadfile` / `*tclopen` return empty). The real, working
open command is:

```tcl
*readfile $modelpath
```

(single-argument form). A 3-argument form `*readfile "hm" $modelpath 0` was
tried first and returned an error (`rc=1`), while the bare `*readfile
$modelpath` succeeded (`rc=0`) and populated the model — confirmed by the
subsequent `comps` markcount = 10, matching the real test model. Also
confirmed present in this install: `hm_comparereadfile` (unrelated,
comparison-only) and `*feoutputwithdata` (export, not import — as expected).

creation path is `*CE_ConnectorCreateByMark <anchor_type> <mark>
spot|bolt|seam|area <layers> components <link_mark> <flag> <ce_config>` —

`*CE_Realize` increased the model's element count). Connectors also do NOT
use the normal `hm_attributeindexmax`/`hm_getvalue dataname=` mechanism
documented elsewhere in this file — they need the separate `hm_ce_*` query
family (`hm_ce_type`, `hm_ce_state`, `hm_ce_size`, `hm_ce_getcollector`,
`hm_ce_getfe`, `hm_ce_detailget`, `hm_ce_info`, etc.).

Full command reference, confidence breakdown, and remaining unverified
commands: see `_clean/docs/HYPERMESH_CONNECTORS_API_REF.md`. Not repeated
here to avoid drift between two copies of the same claim.
